## 0. Что это

Новый сайт **Государственного архива Восточно-Казахстанской области**. Он заменяет старый сайт `e-arhiv.vko.gov.kz`.

- Команда **2try**, хакатон **CODEMASTERS HACKATHON 9.0** (Oskemen Hub).
- Сайт на трёх языках: русский, казахский, английский. Код языка в интерфейсе `ru | kz | en`, в данных `ru | kk | en` (см. §11).
- Сайт одностраничный (SPA) в одном файле `index.html`. Бэкенд — один файл `server.js` на Node.js без npm-зависимостей. Хранилище — JSON-файл.
- Контент перенесён со старого сайта: около 1 200 страниц, новости, статьи, фотоальбомы, 1 712 записей каталога. Факты и тексты не выдуманы. Это правило команды: переносить дословно, ничего не сочинять.

## 2. Запуск

```bash
# 1) один раз: скопировать .env.example → .env и задать ADMIN_PASSWORD (минимум 8 символов, буквы и цифры)
npm start                 # node --env-file=.env server.js → http://localhost:3000
npm run start:public      # то же + публичная https-ссылка через Cloudflare Tunnel (записывается в site-access.txt)
npm test                  # tests/smoke.js
python3 dev/build.py      # пересобрать index.html после правок в dev/
```

Windows: `start-site.bat`. Переменные окружения:

| Переменная | Назначение |
|---|---|
| `PORT` | порт, по умолчанию 3000 |
| `ADMIN_PASSWORD` | пароль пользователя `admin` (роль chief) |
| `ANTHROPIC_API_KEY` | ключ Claude для ИИ-функций. Без него работает встроенный бот и простые локальные запасные варианты |

| `TG_BOT_TOKEN`, `TG_CHAT_ID` | необязательно: копия уведомлений «на проверку» в Telegram (ТЗ 6.7) |

Проверка состояния: `GET /api/health` → `{ok:true, ai:false|true}`. `ai:false` значит, что ключа нет.

## 3. Фронтенд

### 3.1 Сборка
`dev/build.py` читает `src.html` и подставляет на место маркеров:
- `@@TZ_JS@@` / `@@TZ_CSS@@` — содержимое `tz.js` / `tz.css`;
- `@@RK_EMBLEM@@`, `@@CITY_ARMS@@`, `@@SHELVES_SVG_B@@` и т. п. — SVG и картинки (data-URI);
- `content.js` — данные `window.SITE`.
- Основной скрипт, QR-библиотека и данные сайта выносятся в `app.<хеш>.js`, `qr.<хеш>.js` и `site-data.<хеш>.js` (старые файлы с другим хешем сборка удаляет); в `index.html` остаётся короткий загрузчик (раздел 12, «Этап 3»).

Если в тексте `tz.js` (даже в комментарии) встретится строка маркера вида `@@TZ_JS@@`, сборка упадёт на assert.

### 3.2 Роутинг
Адреса строятся на хеше: `#view/tab/rest?query`. Разбор делает `parseHash()`, переключение — `onHash()` → `show(view)` → `TZ.route(view, rest, qs)`.

- `VIEWS` (src.html): `home, visitors, fonds, region, about, news, contacts, admin, page`. tz.js добавляет `catalog, memory, expo, privacy`.
- `#p/<id>` — полная страница старого сайта из `pages/c*.json` (например `#p/1336` «Структура, функции»).
- `#catalog?q=…&type=…`, `#catalog/<id>` — каталог и карточка документа.
- Хабы с вкладками (`HUBS`): например `#visitors/faq`, `#about/history`, `#about/docs`.
- Сервер понимает «красивые» пути (`/catalog`, `/news` …): `seoRoute()` / `serveRoute()` вставляют `<base href="/">`, canonical, title, description и hreflang, а клиент переводит путь в хеш.

## 4. Сервер (`server.js`)

Node ≥ 20.6, без зависимостей. База — объект `db`, который сохраняется в `DATA_FILE` (`save()`). Раз в сутки делается копия в `data/backups/db-ГГГГ-ММ-ДД.json`, хранятся 30 последних.

Структура `db`: `entries` (книга отзывов), `reviews`, `mod` (статусы модерации), `news`, `settings`, `questions`, `photos` (data-URL ≤ 600 КБ, поле `slot`), `users`, `items` (материалы каталога, выставок и памяти, добавленные через админку), `journal`, `stats`.
`db.files` — описания загруженных цифровых копий (сами файлы в `data/files/<id>.<тип>` и `<id>.view.jpg`); `db.catOverrides` — правки и скрытие перенесённых записей каталога.

### 4.1 API
Публичные:
| Метод и путь | Что делает |
|---|---|
| `GET /api/health` | состояние, `ai` есть или нет |
| `GET /api/public` | всё публичное: одобренные отзывы, новости, настройки, фото, опубликованные `items`. У записей `acc:'limited'` вырезаются `img/url/tx` |
| `POST /api/guestbook`, `/api/reviews`, `/api/questions` | отзывы, оценки, вопросы. Попадают на модерацию, есть ограничение частоты |
| `POST /api/assistant` | ИИ-помощник |
| `POST /api/ai/summary` | ИИ-резюме документа |
| `POST /api/stat` | анонимная статистика поиска и просмотров |
| `POST /api/login` | вход `{login,password}` → `{token,user,perms}` |
| `GET /robots.txt`, `/sitemap.xml` | SEO (~1 200 адресов) |
| `GET /files/<id>/view`, `/files/<id>/master` | цифровая копия. Посетителю — только облегчённая копия файла, прикреплённого к опубликованной открытой записи; мастер-копия и неприкреплённые файлы — только сотрудникам (заголовок Authorization) |

Админские (заголовок `Authorization: Bearer <token>`):
`GET /api/admin/state`, `GET /api/admin/me`, `POST /api/admin/logout`, `POST /api/admin/mod`, `DELETE /api/admin/item`, `PUT|DELETE /api/admin/news`, `PUT /api/admin/settings` (≤ 300 КБ), `POST|DELETE /api/admin/photos` (слот `branch` — фото зданий, см. §4.2), `POST /api/admin/files?name=…` (тело — сам файл: JPG, PNG, WebP до 25 МБ, TIFF до 100 МБ, PDF до 50 МБ; тип по первым байтам; PDF с JavaScript, запуском программ или вложениями не принимается), `POST /api/admin/files/<id>/view` (облегчённая копия JPEG до 4 МБ), `DELETE /api/admin/files/<id>` (только не прикреплённый), `PUT|DELETE /api/admin/users`, `GET|PUT /api/admin/catalog` (правка и скрытие перенесённых записей каталога, право `publish`), `PUT /api/admin/perms` (таблица прав ролей, `{matrix}` или `{reset:true}`, только chief), `PUT|DELETE /api/admin/items`, `POST /api/admin/items/bulk` (CSV), `GET /api/admin/stats`, `POST /api/admin/insights` (ИИ-советы по статистике), `POST /api/admin/ocr` (распознавание текста через ИИ).

### 4.2 Роли и права (`ROLES`, `PERMS`)
Роли: `chief` (главный администратор), `admin`, `editor`, `staff`, `branch` (администратор филиала, работает только со своим архивом), `moderator`, `analyst`.

| Право | Роли |
|---|---|
| users | chief |
| journal, settings | chief, admin |
| news, photos | chief, admin, editor |
| mod, publish | chief, admin, moderator |
| items | chief, admin, editor, staff, branch, moderator |
| stats | chief, admin, analyst |
| questions | chief, admin, moderator, analyst |
| ocr | chief, admin, editor, staff, branch |
| brphotos | chief, admin, editor, branch (branch — только фото своего филиала) |

Это **стандартные** права (`DEFAULT_PERMS` в server.js). Главный администратор меняет их в «Пользователи → Права ролей» (ТЗ 6.1–6.2): таблица сохраняется в `db.rolePerms`, `applyPerms()` собирает действующую `PERMS`, права работают сразу, в том числе у вошедших. Что держит сервер: `chief` остаётся в каждой строке; строка `users` не меняется (`LOCKED_PERMS`: иначе можно выдать себе роль chief); неизвестные роли отбрасываются. В `/api/admin/state` таблица приходит как `roleMatrix` (только тем, у кого есть `users`), в журнал пишется разница («news: −editor»). Новое право добавляется в `DEFAULT_PERMS`, а подпись для таблицы — в `PERM_T` и `permXxx` (tz.js).

**Фото зданий** (`slot:'branch'`, id `br-<код>`, код = `p.arch || p.key` из `allPlaces()`: `gavko`, `uka`, `ridder`, `zirian`, `zaisan`, `b<id>`): право `brphotos`; администратор филиала загружает и удаляет только `br-<свой филиал>`; id `br-…` для других слотов запрещён; размер ≤ 200 000 знаков data-URL (клиент сжимает до ~150 КБ). Фото едут в `/api/public` вместе со всеми, поэтому держим их лёгкими; из галереи на главной они исключены. Если зданий станет много, стоит отдавать их файлами по URL.

Сессия закрывается через 60 минут бездействия и не позже чем через 12 часов. Пароли хранятся как scrypt-хеши. После 5 неудачных попыток вход блокируется на 15 минут. Все действия пишутся в журнал (`journal()`). Заголовки: CSP, X-Frame-Options, Permissions-Policy.

### 4.3 Статусы материалов (согласование публикаций)
`draft → review → (rework ↔ review) → approved → published → archived`. Публиковать могут роли с правом `publish`. В публичный API попадают только записи со статусом `published`.

## 5. Админка (`#admin`)

Вход по логину и паролю. Пользователь `admin` получает пароль из `.env`, остальных заводит chief во вкладке «Пользователи».

Вкладки:
- **Сводка**, **Модерация** (отзывы и оценки, рядом счётчик ожидающих), **Новости** (заголовок и текст ru/kk, дата, категория, фото, видео YouTube), **Тексты**, **Фото** (слоты фото на страницах и галерея), **Настройки** (баннер, контакты, …), **Вопросы ассистенту**.
- **Каталог и материалы** (`TZA.tab_items`): создание и правка записей каталога, выставок и памяти, смена статусов, фильтры, CSV-шаблон, импорт и экспорт, кнопка «Найти дубли» (одинаковые название и шифр), счётчик «на проверке» на вкладке.
- **Распознавание (ИИ)**: OCR скана через `/api/admin/ocr` (нужен ключ).
- **Аналитика**: популярные запросы и разделы, запросы без результатов, ИИ-советы.
- **Пользователи** (внизу таблица «Права ролей», видит только chief), **Журнал действий**.
- **Филиалы и соцсети**: список филиалов (адрес, телефоны, часы, координаты, показывать или нет) и ссылки соцсетей в формате `сеть | https://… | подпись`, по одной на строку. Фото убранного из списка здания удаляется вместе с ним.
- **Справка и FAQ** (`TZA.tab_guide`, право `settings`): тексты «О сайте» и «Как искать» на ru/kz/en (разметка `## заголовок`, `- пункт`, `**жирный**`, `[текст](https://…)` или `[текст](#catalog)`), частые вопросы (ответ в той же разметке; сохраняются в `settings.content.faq`), открытые ресурсы (`https://ссылка | ru | kz | en`). Хранится только то, что отличается от стандартного текста (`settings.guide`, `settings.refLinks`), остальное следует за кодом; «Вернуть стандартные тексты» всё стирает. Показ: `guideText()`, `refLinks()` (tz.js), `faqItems()` (src.html, его же использует поиск по сайту). Сервер проверяет эти поля в `validateSettings()`: ссылки только http(s), тексты ≤ 20 000 знаков. Старая вкладка «Тексты» теперь правит только «Об архиве» и список филиалов.
- **Фото зданий** (`TZA.tab_brphotos`, право `brphotos`): по каждому зданию из `allPlaces()` загрузка и удаление фото, которое видно в карточке на странице «Филиалы и контакты» (`placePhoto()` в `Br.card()`). У главного здания, пока своего фото нет, показывается фото команды из сборки. Администратор филиала видит только свой.
- **Цифровые копии** (блок «Цифровые копии: сканы и PDF» в форме записи каталога и в редакторе перенесённых записей, право `items`): загрузка нескольких файлов, проверка типа и размера в браузере и на сервере, облегчённая копия JPEG до 1800 px (TIFF разбирает `Formats.decodeTIFF`), порядок, удаление из записи, скачивание мастер-копии. В карточке на сайте сканы показываются в просмотрщике с листанием страниц (`Cat.page`), PDF — встроенным просмотрщиком (`Cat.pdfHTML`). Запись хранит `files: [{id, k:img|pdf, n, v?}]`; у записи «ограниченный доступ» сервер вырезает `files`.
- **Импорт и экспорт Excel** (там же, где CSV): `.xlsx` читается и пишется `dev/formats.js` (`Formats.readXLSX/writeXLSX`), строки идут через `TZA.rowsToItems` и `/api/admin/items/bulk`; дата-число из Excel переводится в ДД.ММ.ГГГГ.
- **Выставки из админки:** фото экспонатов загружаются кнопкой в форме выставки (`TZA.expoFilesBlock`, строки в `#zf-imgs`), видео — `data.yt` (id YouTube), связанные фонды — `data.fd`; показ в `Expo.one`. После `Store.apiLoad` сбрасываются `Cat.data`, `Expo.data`, `Mem.data`, а открытый раздел перерисовывается.
- **Перенесённые записи каталога** (вкладка «Каталог и материалы», блок внизу, право `publish`, `TZA.catEditBox`): поиск, правка полей, скрытие, возврат исходного. `pages/catalog.json` не меняется; правки в `db.catOverrides`, их накладывает сервер (`catView()` в server.js) при отдаче `/pages/catalog.json` (ETag, `no-cache`), адресов `/catalog/<id>` и sitemap; у «ограниченных» записей вырезаются `img/url/tx`. Если клиент кэширует каталог иначе, смотри `TZD.get` и `sw.js` (network-first для этого файла).
- Вкладок в админке больше десятка: в tz.css они переносятся на новую строку (`#admin-root .tabs`).
- SEO (7.5): `seoHead()` в server.js добавляет полный `og:image`, `og:url`, `keywords` (поле в «Настройки», `settings.seoKeywords`) и `noindex` для записей с доступом «ограниченный»; опубликованные через админку карточки и выставки имеют адреса и sitemap (`dbItem()`).

## 7. Карта (важно, ломалась несколько раз)
- Официальные SDK 2GIS (MapGL и Raster JS API) берут тайлы с `tile*-sdk.maps.2gis.com`. **В сети пользователя эти хосты зависают или отвечают 403**, поэтому карта была пустой.
- Решение — собственная карта `TileMap` в tz.js. Она берёт обычные XYZ-тайлы `https://tile{0-3}.maps.2gis.com/tiles?x={x}&y={y}&z={z}&v=1` (отвечают примерно за 180 мс). Поддерживает перетаскивание, кнопки +/−, двойной клик, Ctrl+колесо и клавиатуру. Метки: главный архив, филиалы, городские точки. При мелком масштабе подписи скрываются (`.far`). Если за 9 секунд не загрузился ни один тайл, показывается схема `MapGis.fallback()`.
- `MapGis.mount` переопределён так, что вызывает `TileMap.build(...)`. Старый код GL и Raster остался как запасной.
- Координаты филиалов `BR_GEO`: Риддер 50.333454, 83.500846; Алтай (Зыряновск) 49.727761, 84.262003; Зайсан 47.468526, 84.874595 (приблизительно).
- Ранее была утечка WebGL-контекстов при перерисовке `Br.render`. Сейчас разметка переиспользуется, а экземпляры карт в отсоединённых блоках уничтожаются (`mountMaps`).
- Демо-ключ 2GIS для SDK действует до 17.11.2026. Для TileMap ключ не нужен.

## 8. ИИ-функции
Все работают по-настоящему только с `ANTHROPIC_API_KEY` в `.env`. Без ключа срабатывают запасные варианты: локальный бот по FAQ и глоссарию, локальное резюме.

Сервер вызывает Claude с `thinking: disabled`: скрытые рассуждения тратят `max_tokens` и обрывают ответ. Системный запрос не длиннее 24 000 знаков (`server.js`, `askAI`). Не используйте `\w` в регулярках для русского текста: он не видит кириллицу.
- Резюме документа (`AiSum`, `/api/ai/summary`).
- OCR в админке (`/api/admin/ocr`).
- Советы по аналитике (`/api/admin/insights`).
- Смысловой поиск в каталоге (`SemQ`) работает без ИИ, на правилах.

## 11. Подводные камни
1. **`index.html` — сборка.** Все правки делаются в `dev/`.
2. **Казахский:** в интерфейсе код `kz`, в данных каталога и страниц `kk`. Для перевода используется `LK()` в tz.js. Машинный перевод на казахский без согласования с командой запрещён (AGENTS.md).
3. **Размеры:** `PUT /api/admin/settings` ≤ 300 КБ (настройки приходят каждому посетителю, не клади туда картинки). Фото ≤ 600 КБ data-URL. Тело материала ≤ 200 КБ.
4. **Service worker** держит кэш. После правок поднимай `CACHE` в `sw.js`. При отладке помогает Ctrl+F5 или удаление SW.
5. **Карта:** не возвращать SDK-тайлы 2GIS (§7). Не создавать новые WebGL-карты при каждой перерисовке.
6. **Скрытые вкладки браузера** (встроенная панель приложения Claude) почти не крутят `requestAnimationFrame`, и IntersectionObserver там не срабатывает. Карты и анимации проверяй в обычном Chrome.
7. **Личные данные:** `data/db.json` хранит отзывы и вопросы посетителей и хеши паролей. Не публиковать и не коммитить. Отзывы публикуются только после модерации.
8a. **Резервные копии:** раз в сутки копируется только `data/db.json`. Цифровые копии лежат в `data/files/` — эту папку нужно сохранять вместе с базой. Файлы, загруженные, но так и не прикреплённые к записи, сервер удаляет через 3 дня.
8. **Секреты:** `.env` и `site-access.txt` содержат ключ и пароль. Не выводить их в чат и в логи.
9. Классы CSS разделов ТЗ имеют свои префиксы (`cat-`, `cr-`, `mem-`, `br-`, `tmap-`, `za-`), чтобы не конфликтовать с базовыми. Например, `.cat-sec` занят главной, поэтому в каталоге используется `.cr-sec`.

  **Этап 2 (11.11.2026): телефон 60 → ≈70 (67–72, оценка колеблется), компьютер 87 → 91, доступность, практики, SEO — 100, сдвиг 0.** Что сделано: (1) первое фото заставки сервер выбирает среди лёгких (файл `-1200` до 150 КБ, `heroBoot` в `server.js`), все `-1200.jpg` пережаты из `-2400` (прогрессивный JPEG, качество 72: 11,1 → 8,4 МБ); (2) `Photos.init` больше не «пробует» скачать фото из `PHOTOS` при старте (≈280 КБ мимо главного кадра), гербы и фото вне первого экрана грузятся лениво (`loading="lazy"`); (3) следующий кадр заставки качается через 2,5 с после загрузки страницы (`Hero.preload`), а не сразу (600–770 КБ мешали главному); (4) панели разделов с вкладками собираются при первом заходе, а не все при старте (`Tabs.refresh` собирает только открытый раздел): TBT 510 → ≈300 мс; (5) `Hero.init` расставляет только первый кадр; (6) сервер сжимает текст в brotli, если браузер его принимает (`packText` в `server.js`: HTML 291 → 252 КБ, данные сайта 135 → 105 КБ; сжатое хранится в памяти); (7) логотип 24 КБ. **Пробовали и откатили:** запуск основного скрипта после первой отрисовки и отложенная загрузка `/api/public` — по LCP выигрыша нет. **Этап 3 (11.11.2026): телефон ≈88 (84–91 в семи замерах), компьютер 98, доступность, практики, SEO — 100, сдвиг 0.** Главное: основной скрипт (620 КБ), данные сайта и QR-библиотека больше не в HTML и не тегами `<script>`: `dev/build.py` выносит их в `app.<хеш>.js` и `qr.<хеш>.js` (рядом с `site-data.<хеш>.js`, сервер отдаёт все три с кэшем на год), а короткий загрузчик в HTML подгружает их **после первой отрисовки** (событие первой отрисовки и загрузка фото заставки, запасной таймер 2,5 с; `async=false` держит порядок: QR, данные, код). HTML стал ≈240 КБ вместо 887 КБ. Почему так: Lighthouse считает главный кадр (LCP) по всем запросам, которые закончились до него; скрипты в этот список попадали, пока грузились раньше первой отрисовки. Ещё: фото заставки объявлено в `<head>` (`heroBoot` в `server.js`, **после `<meta name="viewport">`**, иначе `100vw` считается от 980 px и выбирается лишний файл `-2400`), картинки мозаики главной (`data-src`) и значок 192 (палитра, 19 КБ) не мешают главному кадру. **Как работать с этим:** в `dev/src.html` ничего менять не нужно: основной код по-прежнему внутри `(() => { 'use strict'; … })();`, `dev/build.py` вырезает его по этому началу. Если добавляете новый скрипт, подключайте его в загрузчик (`_loader` в `build.py`). `sw.js` v23 берёт имена файлов из `index.html`. На медленном телефоне при настоящем троттлинге страница рисуется через ≈1,2 с, но основной код доезжает позже: пока он не выполнился, меню и разделы пустые (дольше, чем раньше, зато первый кадр не ждёт). Замер: `npx lighthouse http://localhost:3000` на `start-site.bat`, несколько раз (фото заставки случайное).

### Невозможно без заказчика или внешних ресурсов
- Официальные аккаунты соцсетей и лента из них (нужны ссылки и токены).
- Реальные сканы и полный объём фондов сверх опубликованного на старом сайте; документы ограниченного доступа.
- Полный перечень фондов из .xlsb старого сайта: надёжный разбор без библиотек не гарантирован.
- Официальные переводы длинных текстов людьми; фото зданий филиалов (нет исходников).
- Маршрут по дорогам с расстоянием и временем внутри сайта (нужен платный API маршрутизации).
- Email-уведомления (нет SMTP), настоящий антивирус для загрузок, надёжное распознавание рукописного текста.
- Работающий ИИ без ключа `ANTHROPIC_API_KEY`.
- HTTPS на домене архива, хостинг, Lighthouse на их сервере, регулярные обновления.
- PostgreSQL или Elasticsearch: сейчас JSON-файл, и для хакатона это обосновано (ноль зависимостей, бэкапы). Миграция — большая отдельная работа.
- Предпросмотр TIFF делает браузер сотрудника при загрузке (dev/formats.js); на сервере изображения не обрабатываются.
